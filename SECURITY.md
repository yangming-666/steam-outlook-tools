# Security

Do not include secrets, account exports, personal data, private repository contents, or unredacted logs in public issues or pull requests.

For a suspected vulnerability, use GitHub's private vulnerability reporting option if it is available in this repository's Security tab. If it is unavailable, contact the repository owner through an established private channel; do not publish exploit details or credentials in an issue.

No fixed security-response SLA or supported release matrix is currently published. Use the current source and review the README's operational limitations before running it.

Removing a file from the latest commit does not remove it from Git history. If a real credential was committed, revoke or rotate it and separately assess history cleanup.
